01 — Overview

What this website is, and how it's built

pyportfolios.com is an educational platform that bridges quantitative finance theory with practical Python. The site you see is a marketing landing page plus a small content site (research articles, a course outline, and a literature canon).

In plain English Think of the whole project as a very fancy, fast-loading brochure + library. There is no server doing work when a visitor arrives — every page is pre-baked into plain HTML files ahead of time and simply handed over. That makes it cheap, fast, and hard to break.

The big picture

Pre-rendered

Everything is generated at build time into static HTML (output: "export"). Visitors download files, not computed responses.

Component-driven

The UI is assembled from ~30 small React components (hero, ticker, charts, pricing, etc.) that snap together.

Data-driven

All content (articles, course, books, design variants) lives in plain TypeScript files under src/lib/. No database, no CMS.

02 — Architecture & Build

How the pieces fit together

The site uses Next.js's App Router with static export. Understanding three ideas — static export, server vs. client components, and the data→component→page flow — explains nearly everything.

1. Static export ("no server")

// next.config.ts
const nextConfig = {
  output: "export",   // build into plain HTML files (out/)
};

At build time, Next.js runs every page once, renders the HTML, and writes it to an out/ folder. nginx then serves those files directly.

In plain English Most websites cook each page fresh when you ask for it. This one cooks all the pages in advance and keeps them ready on a shelf. When you visit, you just grab the finished plate. Faster, cheaper, and nothing to crash.

2. Server vs. Client components

React components here come in two flavours. By default they are Server Components — rendered once at build time into HTML, shipping zero JavaScript. A component opts into interactivity by adding "use client" at the top, which means its JavaScript is sent to the browser and runs there.

TypeMarkerRunsExamples
Server (default)—Build time → HTMLStyleTile, Pricing, FAQ, all logo rows, charts
Client"use client"In the browserWorldSphere, WorldClockBand, Lightbox, PageTOC, EarlyAccess, SmoothScroll, ScrollReveal, VersionSwitcher
In plain English Static parts (text, layout, logos) are printed once and need no "brain". Only the genuinely live parts (the spinning globe, the ticking clocks, the click-to-zoom) carry a little JavaScript brain that wakes up in your browser.

3. The data → component → page flow

// data lives as plain TS            // a page reads it          // and renders components
src/lib/articles.ts   ──►   src/app/research/page.tsx   ──►   <ArticleCard/> × N

Content is never hard-coded inside pages. A page imports arrays/objects from src/lib/*, loops over them, and feeds each item into a presentational component. To add an article, course module, or book, you edit a data file — not the layout.

Rendering model summary

Build step

next build → runs generateStaticParams() for dynamic routes, renders all pages, writes out/.

Runtime

Browser loads static HTML + CSS. A handful of client components "hydrate" (attach their JS) for interactivity.

Next.js 16 gotcha: route params are now async. Pages do const { slug } = await params;. The repo's AGENTS.md warns this version differs from older Next.js — always check the bundled docs before editing routing.

The root layout wraps everything

app/layout.tsx is the shell every page lives inside. It loads the three fonts, sets global metadata, and mounts <SmoothScroll/> (Lenis) so momentum scrolling applies site-wide.

// app/layout.tsx (essence)
<html className={lora.variable +" "+ switzer.variable +" "+ courier.variable}>
  <body>
    <SmoothScroll />        // Lenis momentum scrolling
    {children}              // the current page
  </body>
</html>

Dynamic routes & pre-generation

The variant and article routes are dynamic, but the site is fully static — so Next.js needs the list of every valid value up front. That's generateStaticParams(), paired with dynamicParams = false (anything not in the list → 404).

// app/research/[slug]/page.tsx
export const dynamicParams = false;            // only known slugs exist

export function generateStaticParams(){
  return ARTICLE_SLUGS.map(slug => ({ slug })); // build one page per article
}

export default async function ArticlePage({ params }){
  const { slug } = await params;            // Next 16: params is async
  const article = getArticle(slug);
  const Body = BODIES[slug];               // the hand-written prose component
  if(!article || !Body) notFound();
  return <ArticleLayout article={article}><Body/></ArticleLayout>;
}
In plain English Because there's no live server, the site can't invent a page on demand. So at build time it asks each section "give me your full list of items" and prints one page for every one of them. Ask for a URL that wasn't on the list and you simply get a 404.

The variant system

Versions v0–v6 render the same StyleTile component with different feature flags toggled on; v11 ("The Quarterly") renders a separate EditorialTile layout. The flags decide whether extras like the crest, photography, or the live globe appear.

// app/[version]/page.tsx
if(version === "v11") return <EditorialTile/>;
return <StyleTile variant={VARIANTS[version]} />;

See Data & Content for the flag table.

05 — Data & Content

Content as data

The site has no database. Every list of things — articles, course modules, books, design variants — is a typed array in src/lib/. Pages import these and render them. This is the single most important pattern to understand for editing content.

The data files

FileHoldsKey exports
lib/variants.tsThe 8 design versions + feature flagsVARIANTS, VARIANT_IDS, VARIANT_LIST
lib/articles.ts8 research articles + 4 categoriesARTICLES, getArticle(), articlesByCategory(), articleNeighbours()
lib/course.ts7 modules, 28 lessonsMODULES, MODULE_COUNT, LESSON_COUNT, TOTAL_MINUTES
lib/literature.tsBook groups + landmark papersBOOK_GROUPS, PAPERS, counts

Where article prose lives

Article metadata (title, date, reading time, stack, TOC) sits in lib/articles.ts. The article body is a hand-written React component in src/content/articles/<slug>.tsx — not Markdown — so figures and code can be crafted precisely. A small registry wires slug → component:

// research/[slug]/page.tsx
const BODIES = {
  "black-scholes-from-first-principles": BlackScholes,
  "time-value-of-money": TimeValueOfMoney,
  // …8 total
};

Each article also ships a runnable Jupyter notebook in public/notebooks/<slug>.ipynb.

Cross-linking

The data files reference each other by slug strings, validated at build time: a course lesson can link to a research article; a literature paper can link to the article that explains it. Change a slug and the build surfaces the break.

In plain English Adding a new article is like adding a row to a spreadsheet: you fill in its details in articles.ts, write its essay file, drop in its notebook — and the index page, the article page, and any cross-links appear automatically. No layout surgery needed.

Tailwind v4 — CSS-first

There is no tailwind.config.js. Tailwind v4 is configured inside the CSS itself:

/* globals.css */
@import "tailwindcss";
@theme {
  --color-navy: #0a0c14;
  --color-aqua: #1fffff;
  --ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);
  /* …tokens become utilities: bg-navy, text-aqua, etc. */
}
In plain English The whole look is controlled from one short "settings" block at the top of one CSS file. The navy background, the electric-aqua highlight, the heading sizes — all named there once. Designers can re-skin the site by editing a dozen lines instead of hunting through the code.
07 — Motion & Animation

How the site moves

Motion is deliberate and mostly CSS-driven. Two client components provide the "engine" (smooth scroll + reveal-on-scroll); the rest are CSS @keyframes in globals.css. Everything respects the user's "reduce motion" setting.

The two motion engines

SmoothScroll (Lenis)

Wraps native scrolling in eased momentum (duration 1.05s, ease-out-expo). Also intercepts #anchor clicks and glides to them with an -80px offset to clear the sticky nav. Disabled on touch + reduced-motion.

ScrollReveal

An IntersectionObserver adds an in-view class as elements (marked data-reveal) enter the viewport, triggering CSS fade/slide and chart draw-in animations. One-shot per element.

Notable CSS animations

ClassEffect
.hero-inHero text fades + rises on load (staggered by delay)
.draw-line / .draw-pathSVG lines "draw" themselves via stroke-dashoffset (the equity curve, the covariance chart)
.grow-barHistogram bars grow from the baseline, left→right, when scrolled into view
.marqueeThe world-clock ticker scroll (48s linear loop; pauses on hover)
.live-dotPulsing aqua ring on "market open" indicators
.float-curve / .aurora-*Slow ambient drift of the hero curve and background light blobs
.nav-condense / .nav-logoScroll-driven nav padding + logo shrink (CSS animation-timeline: scroll())
.lb-backdrop / .lb-panelLightbox fade + zoom-in

Accessibility: reduce-motion is honoured

/* globals.css */
@media (prefers-reduced-motion: reduce){
  .hero-in,.lb-panel { animation: none; }
  .draw-path { stroke-dashoffset: 0; }   /* show final state, no drawing */
}

The two JS engines bail out early when reduce-motion is set: SmoothScroll never initialises Lenis, and ScrollReveal leaves everything visible.

In plain English The animations are like tasteful stage lighting — they guide your eye (text rises in, charts draw themselves, a ticker glides). But if a visitor has told their device "I get motion sick, calm things down," the site quietly turns the effects off and just shows the finished result.
08 — Key Mechanisms

The clever bits, explained

A few features are worth a deeper look — they're where the engineering is most interesting and most reusable.

① The rotating globe — WorldSphere.tsx

Technical: An HTML <canvas> with a hand-written 3D projection (no Three.js). City latitude/longitude are converted to points on a sphere, rotated each frame, projected to 2D, depth-sorted, and drawn. City labels use a fixed priority list and a greedy overlap check so they never flicker. The canvas scales to devicePixelRatio for crisp rendering, and the spin slows dramatically under reduce-motion.

In plain English It's a tiny hand-built planetarium drawn dot-by-dot, instead of pulling in a heavy 3D library. Lightweight and fully controlled.

② Live world clocks — WorldClockBand.tsx

Technical: Times come from the browser's Intl.DateTimeFormat with each city's IANA timezone (e.g. Asia/Tokyo) — no timezone math by hand. A 1-second interval re-renders; market-open dots compare "now" against open/close minutes and trading weekdays (e.g. Tel Aviv trades Sun–Thu). To avoid a server/browser mismatch, it shows --:-- until mounted, then fills in.

In plain English Each city's clock asks the browser "what time is it there right now?" and ticks every second, lighting a dot green when that market is open.

③ Click-to-enlarge — Lightbox.tsx

Technical: One delegated click listener on the document handles every image/figure tagged data-zoom — no per-image wiring. Photos open on a white panel at intrinsic resolution; SVG charts are cloned onto a dark panel (so they stay theme-correct and infinitely sharp). Esc / backdrop / ✕ close it; focus is trapped and restored; background scroll locks.

In plain English A single "watcher" notices any clickable image and pops a clean, zoomed view over the page — keyboard-friendly and tidy on the way out.

④ On-this-page TOC — PageTOC.tsx

Technical: An IntersectionObserver with a viewport-middle band (rootMargin: -45% 0 -50%) picks the "current" section and highlights its tab (scroll-spy). Clicks are plain #anchor links that fall through to the global Lenis handler for an eased jump.

In plain English As you scroll, the menu automatically underlines whichever section you're reading — and clicking a menu item glides you there.

⑤ Drop-in images — build-time file checks

Technical: Server components like StyleTile (focus photos) and SectorsIndices (provider logos) call fs.existsSync() at build time to detect whether an asset file exists, choosing a real image or a graceful text/placeholder fallback. Drop a correctly-named file into public/ and it appears — no code change.

In plain English The site checks its own image folders while building. Add a logo named the right way and it shows up automatically; leave it out and a neat placeholder stands in.

⑥ Charts are SVG, not images

Technical: ReturnsHistogram and the covariance figure are drawn from hardcoded data arrays into deterministic SVG. That means crisp at any zoom, animatable (bars grow, lines draw), and identical between server render and browser.

In plain English The charts are drawn with math, not saved as picture files — so they're razor-sharp at any size and can animate.
09 — Build & Deploy

From source to live site

The workflow is: develop locally, build to static files, serve those files with nginx.

npm scripts

CommandDoes
npm run devLocal dev server with hot reload (next dev)
npm run buildBuilds the static site into site/out/
npm run lintRuns ESLint
npm run start(Standard Next start — unused for static hosting)

The build output

next build with output: "export" produces a folder of plain files:

site/out/ ├── index.html # home (v0) ├── v1/index.html … # each variant ├── research/index.html # article index ├── research/<slug>/… # each article ├── course/ literature/ parked/ ├── _next/static/… # CSS + JS bundles (hashed) └── flags/ logos/ notebooks/ … # copied from public/

Serving with nginx

nginx points its root at site/out and serves files directly. The repo's deploy/ holds isolated configs (e.g. an instance on port 1133) that run alongside any other site without touching port 80.

# deploy/ (essence)
root  .../site/out;
location / { try_files $uri $uri.html $uri/ /index.html; }
location /_next/static/ { expires 1y; }   # hashed assets cache forever
In plain English You "compile" the website into a folder of finished pages, then point a simple file-server (nginx) at that folder. Updating the site = rebuild the folder and refresh. There's no app to keep running or crash.
Editing checklist: change content in src/lib/* or src/content/* → run npm run build → the static out/ updates → hard-refresh the browser (hashed assets cache aggressively).
10 — Glossary

Plain-English glossary

Quick definitions for the terms used throughout this doc.

TermMeaning
Static exportBuilding the whole site into plain HTML files ahead of time, so no server computes pages on request.
ComponentA reusable, self-contained piece of UI (a button, a card, the whole hero). The site is built by composing these.
Server componentA component rendered once at build time into HTML; ships no JavaScript. The default here.
Client componentA component marked "use client" that runs JavaScript in the browser for interactivity.
HydrationWhen the browser "wakes up" a client component by attaching its JavaScript to the already-rendered HTML.
App RouterNext.js's system where folders under src/app/ become URLs.
Route / slugA URL path; a slug is the readable id in it, e.g. black-scholes… in /research/black-scholes….
generateStaticParamsA function that lists every dynamic page to build (since there's no live server to invent them).
Design tokenA named value (a colour, a size) defined once and reused everywhere — change it once, it updates globally.
TailwindA styling system of small utility classes (bg-navy, text-aqua) plus, in v4, a CSS-based token config.
IntersectionObserverA browser tool that notices when an element scrolls into view — used for reveal animations and the TOC scroll-spy.
LenisThe library that gives the page its smooth, momentum scrolling.
IANA timezoneA standard timezone name like Asia/Tokyo; the browser uses it to compute correct local times.
SVGScalable Vector Graphics — images drawn with math, so they stay sharp at any size and can animate.
CanvasAn HTML element you draw pixels onto with code — used for the rotating globe.
prefers-reduced-motionA device setting where users ask for fewer animations; the site honours it.
Variant / flagA design version (v0–v11); flags are on/off switches that add features like the crest or globe.
