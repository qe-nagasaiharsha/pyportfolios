# pyportfolios

**pyportfolios.com — where finance theory, coding & markets converge.**

A quantitative-finance publication and course site: long-form research articles with
runnable Python companions, a curated library of the books and papers that built
quant finance, and a structured course from first principles to a working backtest.
Built as a fully static Next.js export served by nginx — no Node process, no
database, no backend.

## What the site is

| Route | What lives there |
|---|---|
| `/` | Landing page — hero, capability grid, how-it-works, book shelf, pricing tiers, FAQ, early access |
| `/research` | Article index — four categories, card grid |
| `/research/<slug>` | A research article — dark reading theme, KaTeX math, code cards, figures, sticky ToC with scroll-spy, notebook/project download CTA |
| `/literature` | The canon — ~50 curated books with real cover art and "why it matters" notes, plus landmark papers cross-linked into articles |
| `/course` | "Quant Finance Basics" curriculum — modules and lessons; Module 1 free; lessons link into matching articles |
| `/content` | Content hub overview |
| `/standalone.html` | Portable single-file version of the site (`pyportfolios.html` at repo root) |

Article categories: **Quant Finance Foundations · Portfolio Optimization ·
Risk Management · Algorithmic Trading** (Roman-numeraled, periodical style).

Current articles include Brownian Motion / GBM-on-SPY, Black-Scholes & the Greeks,
Bond Duration & Convexity, Time Value of Money, Hierarchical Risk Parity,
Ledoit-Wolf Shrinkage, VaR/CVaR Three Ways, EVT t-Copula VaR, Pairs Trading via
Cointegration, and Cross-Sectional Momentum.

## Tech stack

- **Next.js 16** (App Router, Turbopack) with `output: "export"` — the build
  produces plain static HTML/CSS/JS in `site/out/`; `next dev` still works
  normally for development.
- **React 19**, **TypeScript**, **Tailwind CSS 4** (via `@tailwindcss/postcss`).
- **KaTeX** for mathematics, **Lenis** for smooth scrolling.
- **nginx** (Windows) serves the export in production — one isolated instance
  per port, nothing shared with other nginx installs on the box.
- Python (NumPy/SciPy/pandas/matplotlib) powers the figure-generation scripts and
  the downloadable project bundles; bundles bootstrap themselves with `uv`.

## Getting started (development)

Requires **Node 22+**.

```bash
git clone <repo-url> -b Bhavya pyportfolios
cd pyportfolios/site
npm install
npm run dev          # http://localhost:3000  (or: npx next dev -p <port>)
```

Everything editable lives under `site/src/`. Hot reload covers article bodies,
catalogues, and styles alike — there is no CMS; content is code.

## Building for production

```bash
cd site
npm run build
```

This runs `next build` with `output: "export"` and writes the complete static
site to `site/out/` (~20 pages: all routes plus one page per article slug).
TypeScript errors fail the build. There is no server bundle — `out/` is the
whole deliverable.

## Deployment (nginx)

Production is an **isolated nginx instance** pointing its web root at
`site/out/`. Each config in `deploy/` is self-contained: its own error log, pid
file, and temp dirs under `deploy/nginx-runtime-<port>/`, so it never collides
with any other nginx on the machine.

```bat
:: Start (public, :5000)
C:\nginx-1.28.3\nginx.exe -p <repo>/deploy/nginx-runtime-5000/ -c <repo>/deploy/nginx-5000.conf

:: Reload after a rebuild          :: Stop
...same args... -s reload          ...same args... -s stop
```

Key config decisions (see `deploy/nginx-5000.conf`):

- `server_name _` + `listen 5000` — answers on the server IP for any host header.
- `try_files $uri $uri.html $uri/ /index.html` — maps clean URLs to the
  exported `.html` files.
- HTML/images: `Cache-Control: no-cache, must-revalidate` (updates show
  immediately); `/_next/static/`: `immutable, 1y` (fingerprinted, safe forever).
- `error_page 404 /404.html`.

**Deploy cycle:** `npm run build` → `nginx -s reload` (reload is not strictly
required for file changes, but clears any open file handles). The site is
reachable at `http://<server-ip>:5000`.

> Note: the `pyportfolios.com` domain currently points at separate hosting, not
> at this deployment. This repo's site is served by IP:port until DNS is
> repointed. The nginx instance is a plain process — it does not survive a
> reboot unless registered as a service or scheduled task.

## Content architecture

The core idea: **metadata lives in `src/lib/`, bodies live in `src/content/`**,
and routes are generated from the catalogues.

### Research articles

- `src/lib/articles.ts` — the catalogue. Each `Article` entry carries slug,
  category, title, dek, date, read time, level, notebook filename, optional
  project zip, optional hero image, section list (drives the sticky ToC and
  scroll-spy), excerpt, and tech stack line.
- `src/content/articles/<slug>.tsx` — the article body as a React component,
  using the shared prose primitives (`components/article/prose.tsx`) for
  paragraphs, math blocks, figures and code cards. Code snippets ship separately
  as `<slug>-code.ts` string modules.
- `src/app/research/[slug]/page.tsx` — the route registry;
  `generateStaticParams` walks the catalogue so every article becomes a static
  page at build time.

**To add an article:** add the catalogue entry in `articles.ts` → create
`content/articles/<slug>.tsx` (+ `-code.ts` if it has snippets) → register the
body in the `[slug]` route → drop figures in `public/figures/`, notebook in
`public/notebooks/`, optional hero in `public/hero/` → build.

### Literature (books & papers)

`src/lib/literature.ts` holds every book: title/author/year, a one-line note,
2–3 "why it matters" bullets, full APA citation for the hover detail layer, and
an optional cover (`public/covers/`, with intrinsic width/height to reserve true
aspect ratio). Books without cover art fall back to a styled typographic cover.
Papers can carry an `article` slug so the library cross-links into the case
studies.

### Course

`src/lib/course.ts` defines modules → lessons ("Quant Finance Basics"). Module 1
is free. Lessons with a matching case study carry an `article` slug and link
straight into `/research/<slug>`.

### Downloadable projects

Each article can ship a self-contained project under `site/project/<slug>/`: the
Python script, a plain-English `README.txt`, and double-click launchers for
Windows/macOS/Linux that bootstrap Python + dependencies via `uv` (users install
nothing). `project/build-zip.py` packs each into `public/downloads/<slug>.zip`,
which the article's CTA links to alongside the notebook.

## Design system

- **Typography:** Switzer (self-hosted, weights 400–900) for UI and headings;
  **Lora** (serif) for article reading bodies; **Courier Prime** for code,
  buttons and tickers. Wired as CSS variables (`--font-switzer`, `--font-serif`,
  `--font-courier`) in `app/layout.tsx`.
- **Theme:** dark editorial — coal backgrounds, pearl text, a single aqua
  accent (the wordmark dot). Bold text inside articles reads bright-white
  against the muted grey body.
- **Article template:** full-bleed hero photograph, sticky table of contents
  with scroll-spy, corner-tick framing on cards, KaTeX display math, hoverable
  header previews, and a notebook/project CTA panel at the end.
- All shared styling conventions live in `site/src/app/globals.css`.

## Utility scripts

`site/scripts/` is one-off tooling, not part of the build:

- `make_*_figures.py` — generate each article's matplotlib figures into
  `public/figures/` (run when an article's analysis changes).
- `fetch_covers*.py`, `isbn_covers.py`, `retry_*.py`, `import_section*.py` —
  book-cover acquisition and literature imports for `/literature`.
- `shoot_*.js`, `measure*.js`, `sweep.js`, `verify.js` — Puppeteer screenshot
  and layout-verification harnesses used during design passes.
- `site/gen-docs.mjs`, root `DOCUMENTATION.html` / `.docx` — generated codebase
  documentation.

## Branches & workflow

- **`main`** — stable baseline ("Harsha stable version").
- **`Bhavya`** — active development branch (currently ~44 commits ahead of
  `main`); this is where all site work happens and what production is built
  from.

The build artifact `site/out/` and `node_modules/` are not meant for review —
treat `site/src/`, `site/project/`, and `deploy/` as the source of truth.
